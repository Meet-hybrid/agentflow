# x402 (planned extension)

**Status: not implemented.** AgentFlow does not claim x402 support.

## What x402 is

x402 revives HTTP `402 Payment Required` for machine-to-machine payments: a server answers an unpaid request with its payment requirements, the client retries with a signed payment payload, and the server (often through a *facilitator* exposing `/verify` and `/settle`) checks and settles the payment before serving the response. The production scheme is `exact` (a fixed price per request).

Stellar has first-party support: developer documentation for agentic payments and a Stellar x402 facilitator, the `@x402/stellar` package (the `exact` scheme with Soroban token transfers, where the client signs only authorization entries and the facilitator submits the transaction), and the `stellar/x402-stellar` examples repository. Several community facilitators also exist.

## Where it fits in AgentFlow

x402 pays **per request** for a service. It does not provide escrow, task verification or dispute resolution, so it does not replace the escrow contract. The natural use is **agents paying for tools while executing a task** (data APIs, model inference, MCP tools):

```mermaid
sequenceDiagram
  participant A as Agent executor
  participant S as Paid API (x402)
  participant F as Facilitator
  A->>S: GET /data
  S-->>A: 402 + payment requirements
  A->>A: check price ≤ task budget policy; sign auth entry
  A->>S: GET /data + payment header
  S->>F: verify / settle
  S-->>A: 200 data
```

Planned design:

- A `PaymentRail` interface in the agent runtime (`quote(requirements)`, `pay(requirements) → header`) with an x402-Stellar implementation, so executors never touch keys directly.
- A per-task spending cap set by the operator and recorded in run logs, with the payment's transaction hash as evidence.
- Separate spending key from the payout key.
- Sandboxed executors would need a narrowly scoped network permission, which Node's permission model does not yet provide; this needs a different isolation layer (container or network namespace).

## Before implementing

- Pin the x402 protocol version (header names differ between v1 and v2 implementations).
- Integration tests against a testnet facilitator, not mocks.
- Decide whether tool costs are reimbursed from the bounty (requires contract changes) or borne by the operator (no contract change; recommended first).
